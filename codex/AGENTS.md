# 사용자 작업 원칙

- 2026-09-25 사용자 결정: 현재부터 모든 작업은 Git으로 관리한다.
- 코드·설정·문서 변경은 해당 Git 저장소의 작업 브랜치에서 수행하고, 검증 결과와 함께 커밋한다. 기존 사용자 변경은 별도로 보존한다.
- 작업 요구사항과 진행 상태는 해당 저장소의 GitHub Issues, 결과 검토는 PR을 기준으로 한다. 실행 기록과 이슈 상태를 구분한다.
- 새 작업도 기존 적합한 저장소를 우선 사용한다. 비밀값·인증 정보·실행 DB·개인 원문은 Git에 넣지 않는다.
- Git 사용 지시는 강제 push, main 직접 병합, 배포, 삭제의 포괄적 승인을 뜻하지 않는다. 요청 범위 안의 일반 구현·검증·커밋·작업 브랜치 push·draft PR은 진행한다.
- 여러 저장소 작업은 충돌하지 않도록 분리하고, 승인된 병렬 실행은 전체 최대 3개·동일 저장소 1개를 기본으로 한다.

## 문서화와 프로젝트 기록

- 모든 문서화, 프로젝트 등의 기록은 Obsidian을 기반으로 작성한다.
- 프로젝트 개요·설계·결정·조사·작업 기록은 Obsidian 호환 Markdown으로 작성하고 Git으로 버전을 관리한다. GitHub에서도 읽을 수 있도록 표준 Markdown 링크를 우선 사용한다.
- 문서 원본은 한 곳에 유지한다. 코드와 함께 검토·배포해야 하는 README, AGENTS.md, API 명세, 운영 문서는 해당 저장소에 두고, Obsidian 프로젝트 노트에서 원본을 연결한다. 같은 본문을 양쪽에서 따로 관리하지 않는다.
- 실제 할 일·진행 상태는 GitHub Issues, 변경 검토는 PR을 기준으로 유지한다. Obsidian에는 배경·결정·결과 요약과 해당 이슈·PR·커밋 링크를 기록한다.
- 기록 전 해당 프로젝트에 지정된 Vault와 문서 위치를 확인한다. 경로가 확인되지 않으면 해당 저장소의 docs/ 또는 기존 문서 위치에 Obsidian 호환 Markdown으로 기록하고, Vault 연결은 미설정으로 명시한다. 특정 Vault를 임의로 공통 Vault로 지정하지 않는다.

이 파일은 Codex의 로컬 지속 지침이며 ChatGPT 계정 메모리와는 별개다.
