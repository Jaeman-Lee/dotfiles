# 실전 관측

Vault 연결 미설정. 진행 상태는 [이슈 #11](https://github.com/Jaeman-Lee/dotfiles/issues/11),
개인 설정 검토는 [이슈 #13](https://github.com/Jaeman-Lee/dotfiles/issues/13),
변경 검토는 [PR #12](https://github.com/Jaeman-Lee/dotfiles/pull/12)에서 관리한다.

사용자가 직접 한 경기를 플레이하는 동안 모니터링하고, 경기 종료 후 PC 성능과
게임 내부 커스텀 옵션까지 고려한 제안을 요청했다. 이후 사용자 종료 알림을 받고
모니터만 중지했다. 사용자는 끊김 없이 정상이고 조작도 괜찮았다고 확인했다.
아래 제안은 관측한 한 구간의 결과이며 모든 맵의 최적값을 확정하는 벤치마크는 아니다.

## 수집과 경계

[관측 도구](../gaming/monitor-cs2-session.py)는 실행 중인 사용자 소유 네이티브 CS2의
PID와 시작 시각을 확인하고, 5초 간격으로 메모리/스왑, CPU 코어별 누적 시간,
게임 RSS·page fault·읽기량, GPU 부하·VRAM·온도·클럭·전력, 디스크와 PSI를 수집한다.
가능하면 1분마다 게임 창 우측 상단 420×80 영역의 성능 HUD만 별도 저장한다.
게임 종료 시 또는 최대 3시간 후 관측만 끝나며 게임에 signal을 보내지 않는다.
설정 변경·프로세스 종료·키보드 입력·패킷 캡처·메모리 주입은 하지 않는다.

관측은 `cs2-live-monitor-20260927.service` 사용자 unit으로 실행한다.
중지는 `systemctl --user stop cs2-live-monitor-20260927.service`이며 게임에 영향이 없다.
실행 원본은 `~/.local/state/cs2-setup/diagnostics/live-20260927/`에 0700/0600으로
보관한다. JSONL, HUD 이미지, 개인 설정 원본은 Git에 포함하지 않는다.

HUD의 평균 FPS·최대 프레임 시간·핑·전송 손실 표본을 읽을 수 있지만
이 수집은 매 프레임 측정이 아니므로 정확한 1% low나 입력 지연 측정으로 표현하지 않는다.
온라인 경기 종료는 게임 프로세스 수명만으로 알 수 없으므로 사용자 종료 알림을 기준으로 분석한다.
사용자가 종료 이벤트 감지를 질문했지만 바로 취소하고 경기 종료를 알렸다.
GSI 구성이나 수신 서비스는 설치하지 않았다.

## 설정 검토 범위

- FHD 120Hz, VSync, 안티앨리어싱, 텍스처/입자/그림자/앰비언트 오클루전,
  HDR/업스케일링, 실제 FPS와 프레임 제한의 균형.
- 가시성과 경쟁 플레이에 영향을 주는 옵션은 단순히 전부 낮추지 않고 비용과 이점을 비교한다.
- Logitech G102 마우스, 감도/줌 감도/조준점/레이더/키 배치/HUD/음향은
  지원 여부와 현재 메뉴 값을 확인하고 사용자 체감을 반영한다.
- 저장된 감도는 2.56, 실행 cfg에는 1.0이 있어 값이 불일치한다. 저장 파일만으로
  현재 런타임 값을 단정하지 않으며 경기 도중 덮어쓰지 않는다. 이후 사용자가 메뉴의
  MOUSE SENSITIVITY=2.56을 직접 확인했다. 하드웨어 DPI는 아직 미확인이다.
- 지원되지 않거나 효과를 검증하지 못한 오래된 콘솔 명령은 성능 개선으로 제안하지 않는다.

## 도구 검증

Python 구문 검사 통과. 실제 실행에서 5초 간격 JSONL과 제한된 영역의 HUD 이미지가
생성되고 관측 unit이 active인 것을 확인했다. 초기 표본에서 모니터 메모리는 약 28MiB,
약 40초 구간 CPU 누적 시간은 약 0.4초였다. 이 값은 관측 오버헤드의 초기 확인이며
게임 성능 결과는 경기 종료 후 별도로 기록한다.

## 실전 관측 결과

20:58:13~21:02:18, 245초 동안 5초 간격 50개 자원 표본과 1분 간격 HUD 5장을
수집했다. 이미 진행 중인 게임에서 시작했으므로 경기 전체를 수집했다고 표현하지 않는다.
HUD 첫 3장은 게임 성능 숫자가 보이고 뒤 2장은 메뉴 배경이며 숫자가 없다.
보수적으로 첫 표본부터 세 번째 HUD까지 120초를 확인된 게임 화면 구간으로 구분했다.

| 지표 | 확인된 게임 구간의 관측 |
| --- | --- |
| HUD 평균 FPS 3개 표본 | 195 / 195 / 208 |
| HUD 최대 프레임 시간 3개 표본 | 7.5 / 8.1 / 7.5ms |
| HUD 핑 | 세 표본 모두 43ms |
| HUD 상·하향 tick miss | 세 표본 모두 0.0% |
| GPU 부하 | 중앙값 84%, 최대 98% |
| GPU 온도 | 최대 70°C |
| VRAM 사용 | 최대 5211MiB / 6144MiB |
| 가용 RAM | 최저 5435MiB |
| 메모리 full PSI avg10 | 최대 0.00% |
| I/O full PSI avg10 | 최대 0.46% |

메뉴까지 포함한 전체 245초에서는 가용 RAM 최저 5183MiB, 스왑 최대 4253MiB,
게임 RSS 최대 6145MiB, 게임 자체 VmSwap 최대 333MiB였다. HDD 사용률 중앙값
1.64%, 최대 22.78%였다. 스왑 사용량 자체를 스래싱으로 해석하지 않는다.
관측 구간 journal에 이전 terminal flush/Steam fatal/GNOME 응답 불가 오류는 없었다.
사용자는 “끊김 없이 정상, 조작도 괜찮음”이라고 답했다.

HUD의 Max 값은 최근 창에서 가장 느린 프레임이며 전체 경기 최악 프레임이나
1% low가 아니다. FPS 세 개를 전체 경기 평균으로 계산하지 않는다.
네트워크 0.0%는 tick miss이며 원시 패킷 손실률 0%의 증거가 아니다.
[Valve HUD 설명](https://help.steampowered.com/en/faqs/view/5E6F-5B36-5485-F6B9)에 맞춰 해석했다.

## 사용자용 권장안 — 아직 미적용

현재 실전에서 안정성과 조작감이 정상이다. OS 이전, 드라이버 교체, 감도 재설정은
필요성을 입증하지 못했다. RTX 2060의 GPU 여유와 전략 정보 가독성을 중심으로
아래를 다음 비교용 후보로 제안한다. 예상 효과는 추론이며 설정별 A/B 측정은 하지 않았다.

| 항목 | 권장 | 이유와 한계 |
| --- | --- | --- |
| 해상도·주사율 | 1920×1080, 전체 화면, 120Hz 유지 | 현재 선명도와 성능이 양호함 |
| FPS 상한 | 게임 200을 다음 비교값으로, 메뉴 60 유지 | 실전 HUD 약 195~208FPS와 간헐적 GPU 98%를 고려한 여유 확보 후보. 현재 240도 안정적으로 관측됨 |
| AA·동기화 | CMAA2, MSAA 끔, 현재 VSync 끔 유지 | 현재 Vulkan/Linux 조합에서 검증한 기준 유지. VRR/Reflex 미검증 상태에서 Windows용 지침을 일괄 적용하지 않음 |
| 텍스처·필터 | 현재 유지 | VRAM 최대 약 5.1GiB/6GiB로 고갈 증거가 없어 먼저 낮출 필요 없음 |
| 파티클·AO | 파티클 낮음, AO 끔을 우선 비교 | GPU가 높은 부하에 닿는 구간을 줄일 후보. 실제 FPS 개선량은 미측정 |
| 그림자·적 대비 | 그림자 높음, 동적 그림자 전체, 플레이어 대비 켬 유지 | 가시성 정보 보존. 모든 그림자를 끄는 일괄 최저 설정은 제안하지 않음 |
| 감도·조준점 | 메뉴 감도 2.56과 현재 조준점 유지 | 사용자가 편한 조작감 확인. DPI 모르는 상태에서 eDPI를 계산하거나 특정 프로 감도를 복제하지 않음 |
| 레이더 | 배율 0.4, 중앙 고정 끔, HUD 레이더 크기 1.1 | 현재 배율 0.7보다 넓은 맵 정보를 보는 출발점. 가독성에 따라 0.4~0.5 조절 |
| 음향 | 효과음 유지, 라운드 종료/MVP 음악 0, 10초 경고는 메뉴에서 10~20% | 전투 외 음악을 줄이고 폭탄 시간 정보는 유지하는 취향 제안. 청각/장비 측정은 하지 않음 |
| 네트워크 | 현재 유지 | 표본 핑 43ms, tick miss 0.0%. 추가 버퍼링으로 지연을 늘릴 근거 없음 |

동적 그림자 옵션과 FPS 상한 메뉴는
[Valve 패치 노트](https://store.steampowered.com/news/posts/?appids=730&enddate=1719355135&feed=steam_community_announcements)를
참조하고, 실제 로컬 설정의 존재를 확인했다. 표의 수치는 사용자용 후보이지 Valve의 권장값은 아니다.

## 실제 반영한 수정

새 최적화 옵션은 아직 적용하지 않았다. 사용자가 실제 메뉴 감도 2.56을 확인했고
현재 조작감을 선호하므로, 다음 실행 때 초기 기본값 1.0으로 되돌아갈 수 있는
`workstation.cfg`의 `sensitivity` 강제 줄만 제거했다. 개인 cfg 두 사본은 로컬
백업 후 갱신하고 게임 저장 파일의 2.56은 그대로 보존한다. 실행 중 콘솔 명령이나
설정 재적용, 게임 종료는 수행하지 않는다.
