# iPad 한글 입력 및 Codex 세션 연결 진단

문서 원본은 이 파일이다. 지정 Obsidian Vault 연결은 미설정이다.
요구사항·진행 상태: [이슈 #20](https://github.com/Jaeman-Lee/dotfiles/issues/20).
기존 입력 운영 절차는 [Ubuntu 웹 원격 화면](ubuntu-web-desktop.md#ipad)을 따른다.
실행 로그·대화 원문·세션 식별자·인증 정보는 기록하지 않는다.

## 확인 결과

14:47–14:51 KST에 읽기 전용으로 확인했다. 해당 시점의 관측이며 간헐적인 장애를 배제하지 않는다.

- CPU 유휴 비율 약 90%, 가용 메모리 약 6.9 GiB였다. 지속적인 전체 자원 포화는 관찰되지 않았다.
- SSD swap 8 GiB 중 약 6.9 GiB가 사용 중이었지만 표본 구간 swap-in은 초당 약 12–36 KiB,
  swap-out은 0이었다. swap 사용량 자체를 현재 지연 원인으로 단정하지 않는다.
- 기본 게이트웨이 ICMP 5회는 손실 0%, 평균 약 0.22 ms였다. iPad에서 PC까지의 원격 구간 측정은 아니다.
- ChatGPT Codex 경로는 비인증 HEAD 요청에 405로 응답했다. 연결 도달만 확인하며 모델 응답 성공을 뜻하지 않는다.
- 기존 Codex 터미널 프로세스 세 개에서 `account/rateLimits/read timed out in TUI`가 반복됐다.
  로컬 제어 소켓의 handshake 미완료 및 연결 해제 로그도 있었다. 이 기록만으로 모델 요청 실패 원인을 확정할 수 없다.
- 현재 진단 세션은 모델 응답과 도구 실행이 가능했다. 기존 세 세션이 복구되었다는 증거는 아니다.
- `codex app-server daemon version`에서 CLI 0.157.0, 실행 중 daemon 0.158.0을 확인했다.
  버전 차이는 추가 확인 대상이며 호환성 문제가 원인이라고 단정하지 않는다.

## 한글 입력 안내

기존 운영 문서에는 Guacamole Text input 경로에서 한글 누락과 PC 입력기의 영문 재해석을
실제 호스트에서 재현한 기록이 있다. iPad 사용자는 하단 **글쓰기**의 흰 입력칸에서
문장을 완성하고 **전송 ↵**을 누르는 기존 기능을 우선 사용한다.
실제 사용 중인 브라우저·원격 앱, 외장/화면 키보드 여부와 이 입력칸에서도 문제가 발생하는지는 확인이 남았다.

## 검증과 남은 확인

`node --test remote-desktop/tests/mobile-input.test.cjs`: 기존 회귀 테스트 9개 통과.
이는 전송 순서·중복 방지·초안 보존 검증이며 iPad 실기기 한글 조합 성공을 증명하지 않는다.

소스 코드, PC 입력기 설정, 원격 서비스와 Codex 실행 상태는 변경하지 않았다.
기존 세션이나 daemon을 재시작하지 않았다. 미전송 입력과 실행 중 작업을 보존했다.
실제 오류 문구와 영향받는 세션의 연결 상태를 확인한 뒤 복구 범위를 결정한다.
한글 입력 문제와 세션 연결 문제 모두 해결 완료로 처리하지 않는다.
