# Ubuntu PC의 Counter-Strike 2 설치 환경

Vault 연결 미설정. 이 문서를 Obsidian 호환 Markdown 원본으로 관리한다.
실제 진행 상태는 [이슈 #11](https://github.com/Jaeman-Lee/dotfiles/issues/11),
변경 검토는 [draft PR #12](https://github.com/Jaeman-Lee/dotfiles/pull/12)를 기준으로 한다.
설정 구현은 [커밋 36656bf](https://github.com/Jaeman-Lee/dotfiles/commit/36656bf)에 기록했다.

## 환경과 선택

- Ubuntu 26.04.1 LTS, AMD Ryzen 5 5600X, NVIDIA RTX 2060 6GB, RAM 약 16GB.
- NVIDIA 드라이버 595.91.07을 유지하며 동일 버전의 i386 그래픽 라이브러리를 설치한다.
- Ubuntu 저장소의 `steam-installer`, `steam-devices`, 양쪽 아키텍처의 Vulkan 로더,
  검증용 `vulkan-tools`를 사용한다. 설치 시 패키지 제거를 허용하지 않는다.
- CS2의 Linux 버전을 사용한다. Proton을 강제 적용하지 않는다.
  후속 승인된 화면/성능/입력 설정은 [개인 게임 프로필](cs2-gaming-profile.md)에 기록한다.
- `/mnt/dev-ssd/games/Steam`에 클라이언트와 게임 데이터를 저장한다.
  홈의 `.local/share/Steam`, `.steam/root`, `.steam/steam` 링크로 연결한다.
  기존 Steam 설치가 다른 곳에 있으면 자동 이동/덮어쓰기하지 않고 중지한다.
- 로그인 정보, 다운로드한 클라이언트, 게임 파일과 실행 로그는 Git에 저장하지 않는다.

## 재현

저장소 루트에서 다음을 실행한다. 첫 명령은 데스크톱 관리자 인증을 요청한다.

```bash
pkexec /usr/bin/bash "$PWD/gaming/install-steam-system.sh"
bash gaming/prepare-cs2-user.sh
steam steam://install/730
```

시스템 설치 스크립트는 이 PC의 Ubuntu amd64 / NVIDIA 595 환경에 맞춘 것이다.
다른 드라이버 계열이나 기존 Steam 설치를 위한 일반 마이그레이션 도구는 아니다.
Steam 최초 설치 안내 후 개인 계정으로 로그인한다. 계정 비밀번호/Steam Guard 코드는
Steam에 직접 입력한다. 게임 다운로드를 마치면 앱 목록의 Counter-Strike 2로 실행한다.

## 검증

- `bash -n`: 두 설정 스크립트 구문 검사.
- 저장 경로 준비 스크립트를 반복 실행하여 동일 SSD 링크를 유지함을 확인.
- `desktop-file-validate`: Counter-Strike 2 바로가기 형식 검사.
- `dpkg --audit`: 출력 없음. Steam 설치 패키지와 양쪽 아키텍처의 NVIDIA/Vulkan
  라이브러리 모두 `ii` 상태 확인.
- `vulkaninfo --summary`: NVIDIA GeForce RTX 2060, NVIDIA 595.91.07,
  Vulkan API 1.4.329 인식 확인.
- `steam steam://install/730`으로 클라이언트 설치/업데이트 완료.
  Steam 실행 프로세스와 `Sign in to Steam` 로그인 창 확인.
- 사용자 로그인 완료 후 CS2 및 Steam Linux Runtime 다운로드 시작을 확인했다.
  manifest 기준 다운로드 약 61.4GB, 설치 데이터 약 74.3GB이다.
- 2026-09-27 사용자가 CS2 정상 구동을 확인했다. 설치 및 실행 목표는 완료했다.
  실행 확인의 근거는 사용자 보고이며, 에이전트의 게임 화면 직접 관찰이나
  맵 내 FPS/프레임 시간 벤치마크를 의미하지 않는다.
- 이후 터미널/게임 종료와 데스크톱 지연이 보고되어 이슈 #11을 다시 열었다.
  [안정성 조사](cs2-desktop-stability-20260927.md)에 관측과 조치를 기록한다.

## 다운로드 속도 진단 (2026-09-27 18:34 KST)

- Steam 최근 다운로드 속도는 약 79~91Mbps, 약 9.9~11.4MB/s였다.
- `ethtool enp10s0`에서 실제 링크는 100Mb/s, Full duplex, 자동 협상 켜짐이다.
  PC는 1000baseT/Full을 지원하고 광고하지만, 연결 상대는 10/100Mbps만 광고한다.
- SSD I/O 지연·사용률과 CPU/메모리 관측에서는 다른 주요 병목이 보이지 않았다.
  현재 다운로드는 100Mbps 유선 링크 한계에 가깝다.
- 공유기/스위치 포트의 기가비트 지원과 설정, 랜선/벽 배선 상태를 먼저 확인한다.
  사용자는 Windows에서도 동일한 벽 포트와 랜선을 사용했다고 확인했다.
  당시 실제 링크 속도는 확인되지 않아 운영체제 또는 배선 문제로 단정하지 않는다.
- 링크 재협상·강제 속도 지정·네트워크 재시작은 수행하지 않았다.
  다운로드 중 manifest 누적 바이트 값이 갱신되지 않아 남은 시간을 계산하지 않았다.
- 검증: 실제 링크 광고 정보와 Steam 속도 로그를 재확인하고 문서 diff를 검사했다.
  계정 정보나 원본 로그는 저장하지 않는다.

### 동일 배선 확인 후 추가 진단

- Realtek RTL8168h/8111h에 커널 `r8169` 드라이버가 사용 중이다.
  부팅과 이후 재연결 기록 모두 100Mbps/Full이다. 조회한 커널 기록에 관련
  펌웨어 로딩 실패는 없고, 인터페이스 RX/TX error 카운터는 0이다.
- NetworkManager 프로필은 speed=0, duplex 미지정이다. auto-negotiate=no여도
  이 조합은 링크 설정을 건너뛰므로 100Mbps 강제 설정을 의미하지 않는다.
  실제 장치 자동 협상은 켜져 있고 1Gbps를 광고한다.
- EEE는 enabled이지만 inactive다. 현재 자료로 절전 기능이나 드라이버가
  원인이라고 확정할 수 없다. 드라이버 교체 또는 영구 설정 변경은 하지 않았다.
- 다음 구분 실험은 연결 중단이 가능한 시점에 랜선을 재연결하고 링크 속도를
  재확인하는 것이다. 계속 100Mbps이면 다른 케이블/기가비트 포트 직결과
  다른 커널 또는 Windows의 실제 링크 속도 비교로 원인을 좁힌다.
- 설정 의미는 [NetworkManager 공식 문서](https://networkmanager.pages.freedesktop.org/NetworkManager/NetworkManager/nm-settings-nmcli.html)의
  `802-3-ethernet.auto-negotiate` 설명과 대조했다.
